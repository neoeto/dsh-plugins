# dsh-plugins

A collection of DeepSeek Harness web plugins. Each plugin lives in its own
directory and is mounted into a `dsh` process through a profile's
`dsh.profile.bundles`.

## Plugins

| Plugin | Description | Docs |
| --- | --- | --- |
| [`dsh-d2-diagram`](./dsh-d2-diagram) | Displays D2 diagrams generated by the `d2_render` tool inline in the conversation, with zoom, pan, source viewing and download | [中文](./dsh-d2-diagram/README.md) · [English](./dsh-d2-diagram/README.en.md) |

## Directory conventions

- One directory per plugin, e.g. `dsh-d2-diagram/`;
- `package.json` declares `dsh.client` (web client entry,
  `exports["./client"]` pointing at the bundle) and `dsh.bundle.patch`
  (the profile-bundle patch layer);
- `cordis.patch.yml` is the bundle patch layer: an empty array for
  display-only plugins; insert host rows there when needed;
- `lib/client.js` is served directly by the harness client-modules service at
  `/plugins/<id>/client.js` — no build step required;
- Every plugin ships two docs: `README.md` (Chinese by default) and
  `README.en.md` (English).

## Mounting

Declare a link dependency and add the plugin to `dsh.profile.bundles` in the
target profile (e.g. `~/.dsh/profiles/web`):

```jsonc
// ~/.dsh/profiles/web/package.json
{
  "dependencies": {
    "dsh-d2-diagram": "link:/path/to/dsh-plugins/dsh-d2-diagram"
  },
  "dsh": {
    "profile": {
      "bundles": ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app", "dsh-d2-diagram"]
    }
  }
}
```

## Development and verification

- After editing `lib/client.js`, refresh the page to pick up the change
  (bundles are served with `no-cache`);
- The rev in the boot manifest is re-hashed after the `dsh` process restarts;
- A running process reads the bundle from the path recorded at startup, so a
  recreated file is served without a restart.
